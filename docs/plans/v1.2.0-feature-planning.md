# AI Guard v1.2.0 功能规划

**规划日期：** 2026-05-24  
**目标发布：** 2026-06-01  
**当前版本：** v1.1.3

## 版本目标

v1.2.0 将专注于提升用户体验和功能完善，主要方向：
1. **进程管理增强** - 白名单功能，永不终止关键进程
2. **配置界面优化** - Web UI 配置界面，无需手动编辑 TOML
3. **数据分析增强** - 历史数据分析，24 小时/7 天趋势
4. **告警系统增强** - 更灵活的告警规则和通知方式
5. **内存优化** - 降低应用本身的内存占用

## 功能清单

### 1. 白名单功能（高优先级）

**需求描述：**
- 用户可以将关键进程加入白名单，这些进程永远不会被自动终止
- 白名单支持进程名、PID、命令行匹配
- 白名单配置持久化到 config.toml

**技术设计：**

```toml
# config.toml 新增配置
[whitelist]
# 进程名白名单（精确匹配）
process_names = ["Claude", "Cursor", "VS Code"]

# 命令行关键字白名单（包含匹配）
command_keywords = ["important-task", "production"]

# PID 白名单（临时，重启后失效）
pids = []
```

**实现步骤：**
1. 修改 `aigard/core/advisor.py`，新增白名单检查逻辑
2. 修改 `aigard/core/threads.py`，自动终止时跳过白名单进程
3. 新增 Web API：
   - `POST /api/whitelist/add` - 添加到白名单
   - `POST /api/whitelist/remove` - 从白名单移除
   - `GET /api/whitelist` - 获取白名单列表
4. 修改 Web UI，在进程列表中显示白名单标记（⭐）
5. 添加"加入白名单"按钮

**UI 设计：**

### 3. 历史数据分析（中优先级）

**需求描述：**
- 保存更长时间的历史数据（24 小时/7 天）
- 提供趋势分析图表
- 识别内存/Swap 使用高峰时段
- 导出历史数据为 CSV

**技术设计：**

**数据存储方案：**
```python
# 使用 SQLite 存储历史数据
# ~/.aigard/metrics_history.db

CREATE TABLE metrics_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp INTEGER NOT NULL,  -- Unix 时间戳
    mem_percent REAL,
    swap_percent REAL,
    disk_percent REAL,
    cpu_percent REAL,
    ai_process_count INTEGER,
    ai_process_mem_gb REAL
);

CREATE INDEX idx_timestamp ON metrics_history(timestamp);
```

**数据采集策略：**
- 每 1 分钟保存一次数据点（降低频率，减少存储）
- 保留 7 天数据，自动清理旧数据
- 内存中仍保留 150 个点（2.5 分钟）用于实时图表

**新增 API：**
```python
GET /api/history/range?start=<timestamp>&end=<timestamp>  # 获取时间范围数据
GET /api/history/summary?period=24h|7d                    # 获取汇总统计
GET /api/history/export?format=csv|json                   # 导出历史数据
```

### 4. 告警系统增强（中优先级）

**需求描述：**
- 支持自定义告警规则（组合条件）
- 支持多种通知方式（macOS 通知、邮件、Webhook）
- 告警静默时段（夜间不打扰）
- 告警优先级分级

**技术设计：**

**告警规则配置：**
```toml
# config.toml 新增配置
[[alert.rules]]
name = "内存和 Swap 双高"
condition = "mem_percent > 70 AND swap_percent > 60"
level = "crit"
message = "内存和 Swap 同时过高，建议立即清理"

[[alert.rules]]
name = "AI 进程内存过高"
condition = "ai_process_mem_gb > 10"
level = "warn"
message = "AI 进程总内存超过 10GB"

[alert.notification]
# 通知方式
methods = ["macos", "webhook"]

# Webhook 配置
webhook_url = "https://example.com/webhook"
webhook_headers = { "Authorization" = "Bearer xxx" }

# 静默时段（24 小时制）
quiet_hours = { start = "23:00", end = "08:00" }
```

**实现步骤：**
1. 修改 `aigard/core/alerter.py`，支持自定义规则
2. 新增规则解析器（简单的表达式求值）
3. 新增 Webhook 通知支持

### 5. 内存优化（中优先级）

**需求描述：**
- 降低应用本身的内存占用
- 优化数据结构和采集频率
- 延迟加载非必要模块

**优化方向：**

1. **减少历史数据保存量**
   - 当前：150 个点（每秒采集）
   - 优化：100 个点（每 1.5 秒采集）
   - 节省：~33% 内存

2. **优化 psutil 采集**
   - 只采集需要的指标，避免全量采集
   - 缓存进程信息，减少重复查询

3. **延迟加载模块**
   - FastAPI 路由按需加载
   - Chart.js 等前端库使用 CDN

4. **优化数据结构**
   - 使用 `__slots__` 减少对象内存
   - 使用生成器替代列表

**实现步骤：**
1. 使用 `memory_profiler` 分析内存使用
2. 优化 `aigard/core/monitor.py` 采集逻辑
3. 优化 `aigard/core/threads.py` 线程管理
4. 测试优化效果
